## 4. 明天第一步：`bsp_adc`

### 4.1 接口（按指示）

```c
void     BSP_ADC_Start(void);            /* 等价 Legacy adc.c:62-64 ADC_Cmd(ADCx, ENABLE) */
uint16_t BSP_ADC_ReadBus(void);          /* ADC1 / PB1 / CH9 = PM1_VBUS */
uint16_t BSP_ADC_ReadCurrentV(void);     /* ADC2 / PA6 / CH6 = PM1_AMPV */
uint16_t BSP_ADC_ReadCurrentW(void);     /* ADC3 / PA3 / CH3 = PM1_AMPW */
void     BSP_ADC_ReadAll(uint16_t *bus, uint16_t *v, uint16_t *w);
```

`BSP_ADC_ReadAll()` 为组合接口——Legacy `ADC_ProcessData()` 确实需要，
**必须严格复现 §1.8 的 6 次读取次数与顺序**。

### 4.2 实现约定

```c
/* 单次读 */
HAL_ADC_PollForConversion(hadc, HAL_MAX_DELAY);   /* 等价 while(EOC==RESET)，无限等待 */
return (uint16_t)HAL_ADC_GetValue(hadc);
```

**禁止**：DMA / Injected / ADC IRQ / 平均滤波 / 每路只采一次 / 中值滤波 / batch。
**不加**：超时恢复、错误状态机（V2 再谈）。
**不改**：CubeMX 初始化。

`ContinuousConvMode=ENABLE` + `ExternalTrigger=TIM1_CC1` + `Falling` + `480 cycles` 全部保持。

**一处需登记的差异**：Legacy `ADC_GetValue` 每次都调 `ADC_RegularChannelConfig`；
HAL 侧**不调用** `HAL_ADC_ConfigChannel`——因为通道已由 `MX_ADCx_Init` 配成同值，重配是 no-op，
且该 HAL 函数有 ADC 使能状态副作用。此差异需写入差异登记表，不得静默。

### 4.3 ⚠️ 依赖关系（实施时必须注意）

**ADC 的外部触发是 `TIM1_CC1`，因此 ADC 转换依赖 TIM1 计数器在运行。**

- Legacy：`TIM1_Int_Init()` 里的 `TIM_Cmd(TIM1, ENABLE)` 保证了这点
- 当前 V1：TIM1 计数器由 `BSP_PWM_Start()` **隐式启动**（`HAL_TIM_PWM_Start` 内部会 `__HAL_TIM_ENABLE`）
- 若 TIM1 未运行 → 无 CC1 事件 → EOC 永不置位 → `PollForConversion(HAL_MAX_DELAY)` **永久阻塞**
- **处置**：暂不修改；在 bsp_timer 阶段统一规划启动顺序，并向用户报告此隐式依赖
