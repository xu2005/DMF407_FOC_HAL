## 使用与状态契约

纯算法：`Motion_ProfileLegacyConfig` → `Motion_ProfileBuild` → `Motion_Init` → 一至100次 `Motion_Enqueue` → `Motion_Start` → 重复 `Motion_Next/Confirm`。profile 在 Motion 生命周期内保持有效且不可修改。每个 Motion 由一个执行主体串行访问；调用方需要跨主循环/IRQ使用时自行明确同步策略。本次 App 的 Motion 只由 main 操作。

默认配置：show_speed=200、Position_Limit=1000、步距角=1.8°、细分16、flexibility=4、Vmin=1、Tmax=300。表有375个样本及一个末项。构建器保留原公式夹限；配置接口允许参数化，不宣称未冻结的非默认参数有原版验收证据。

`Motion_Next` 返回序列号、轴、正/负方向、周期及事件后的计划 XY；有 pending 时不能继续规划。仅匹配序号的成功 `Motion_Confirm` 更新确认 XY；拒绝消费锁存 Motion_FAULT。目标、计划和确认位置分别保存。事件数是生命周期内累计发出的/接受的事件数，取消的 pending 不算确认；重新开启批次不重复使用事件序号。

`Motion_Cancel` 丢弃未消费事件与队列，保留最后确认位置；故障不可被取消清除。`Motion_Rearm` 只接受完成或取消状态，从确认位置启动新批次并重新初始化速度索引，属于明确新增的批次协议。Motion_Init 重新创建纯软件上下文，不解除 BSP 故障锁存。

App：`App_NoPower_GetMotionSnapshot` 可从 main 读回目标/计划/确认 XY、事件数、队列剩余、表索引及末事件；`App_NoPower_CancelMotion` 仅取消软件轨迹。底层 BSP 故障在下一次 main poll/readback 映射为 Motion_FAULT。模拟确认表示软件接收，**不是编码器或物理运动确认**。

App 的 period 是轨迹字段；一次 main poll 不是该 period 的真实经过时间。本次不修改 TIM4 ARR/CCR/引脚，不把纯逻辑消费称为原版物理脉冲调度。TIM4 仍为诊断时基，TIM2 与潜在第二轴资源冲突仍需硬件/设计确认。

## 有意修复与兼容细节

- 原版 S 表可能超过容量。本实现最多写3000个样本及末项；失败使元数据无效，部分表不得消费。speed=1627 恰好占满3000个样本，1628开始超限，返回容量错误；高速度也不会越界。
- 原版错误输入可能导致除零、非法整数转换或时间不前进；本实现校验必要输入/派生值，对此类路径不宣称结果等价。
- 原版 speed_plane 会读空尾槽，data_save/read_ptr 无完整边界；改为明确 head/count 的100槽环形队列，在 Start 时封闭当前批次。满队列拒绝新增，运行中禁止改变正在规划的批次。
- 负位移原版方向处理被注释，计数可能无法到达终点。新代码对幅值递推并携带方向，终点验证覆盖各象限；这是有意修复，不声称错误路径等价。
- 使用固定宽度位置/宽中间量，处理缩放越界和 INT32_MIN→INT32_MAX 增量，避免原版 long 差值/绝对值溢出。
- 保留原版 Time4_Init 在 cul_Saccdec 前的初始化顺序效果：初始逻辑周期10000；Y主轴首个X次轴事件用10000，随后主轴事件才更新表周期。
- busy-wait 改为逻辑事件与确认；周期不直接落到未知硬件资源。

| Host Release | 104/104，失败0 |
| ARM Debug CONTROL=OFF / ON | 两组合configure/build均exit0，ELF/MAP/BIN/HEX生成 |
| ARM Release CONTROL=OFF / ON | 两组合configure/build均exit0，ELF/MAP/BIN/HEX生成 |

原86项名称保留，新增18项标签 `V22_MOTION`：profile_vectors/input/clamps/capacity；motion_vectors/batch_vectors/quadrants/queue/boundaries/cancel_fault/segments/index；app_motion/app_motion_cancel/app_motion_fault分别在OFF/ON运行。累计208次完整Host调用，失败0。3项 `KNOWN_RISK` (`encoder_r01`、`math_angle_r01`、`svpwm_zero`) 的通过表示原风险复现，未关闭风险。已有 ADC→角速→Clarke/Park→PI→Inverse Park→SVPWM 回归随完整测试执行；未另建审计体系。

独立冻结向量由 `scripts/freeze_motion_vectors.py` 从未改动 Legacy 函数抽取并原生执行：5组S曲线完整表；9组单段轨迹及3组正向多段规划的完整axis/period/XY序列摘要，另有短轨迹逐事件冻结表。原版脉冲函数仅替换为记录器，表容量守卫只拒绝溢出，不改变有效路径。测试不从新实现反推期望。

归档：`Docs/审核证据/v22_20261011/commands.json`、Host JUnit、原始configure/build/test日志、逐项 `test-results.csv`。CSV status=run是CTest原始执行状态，实际PASS由对应JUnit无failure和原始CTest exit0/104通过共同证明。本机原目录为 `build/v22-evidence`，ARM镜像为 `build/v22-arm-{debug,release}-{off,on}`。ARM RAM各11744B；Flash分别28424/41012/20112/29932B（DebugOFF/ON、ReleaseOFF/ON）。

ARM仍有既有HAL空编译单元、unused Banks和链接RWX LOAD警告；不宣称零警告。未改依赖版本、未重算1442项哈希、未覆盖V2.1证据。
