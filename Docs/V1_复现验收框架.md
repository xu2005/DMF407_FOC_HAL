## 2. 五级复现验收

| 级别 | 含义 | 判据 | 当前状态 |
|---|---|---|---|
| **L1** | 源码等价 | 函数映射、常数、类型、方向、分支完整核对 | 部分完成（D-01~D-20 已登记；D-20 为有意安全偏离） |

## 4. 不能无条件复现的项

| # | 发现 | 处置 |
|---|---|---|
| 1 | 两版编码器源码相同 | 可复用既有逻辑，无须重写角度算法 |
| 2 | `Speed_Kp` 0.02 → 0.08 | 两版调参结果不同，**禁止混用** |
| 3 | `Speed_Ki` 0.0001 → 0.0015 | 速度环动态特性可能明显不同 |
| 4 | `enable_flag` 0 → 1 | **复现调试行为可能导致不安全启动**（见 R-03） |
| 5 | ADC 轮询可能无限等待 | 必须保留差异证据，不能仅凭 API 替换认定时序等价（D-10） |
| 6 | TIM3 HAL 启动函数可能额外开 CC 中断 | 必须比较**寄存器级行为**，而非只比函数名（D-12） |

### 4.1 两类验收目标要分开

| 目标 | 范围 |
|---|---|
| **功能行为复现** | 保持 `Template222_A` 的控制公式、参数、方向定义、调度关系与数据处理次序 |
| **安全运行验收** | 单独检查驱动禁能、BKIN、过流、复位与急停链路 |

> **冻结原有控制参数是正确的；冻结危险的实际输出状态则没有必要。**
> 但任何有意偏离 Legacy 的安全措施，都必须在差异登记表中说明。

## 6. 重点风险登记

### R-01 编码器 CNT 与溢出计数不同步 ⚠️

**现象**：`gtim_get_encode()` 非原子地读「CNT」与「溢出计数」，两次读之间若发生环绕，会产生 **±65536 跳变**。

**竞争窗口的真实机理（硬件回绕 ≠ 软件计数）**：

| 时刻 | 硬件 CNT | 软件 `g_timx_encode_count` |
|---|---|---|
| T0 | `65535` | `n`（旧值） |
| T1（硬件自动回绕） | **`0`** | `n`（**仍是旧值**，等待 TIM3 ISR） |
| T2（TIM3 Update ISR 执行） | `0` | `n±1` |

**只要任何读方（ISR 或主循环）落在 T1–T2 窗口内**，`CNT + overflow*65536` 即产生 **±65536 误差**。

> ★ **本节此前结论有误，现予纠正**：
> 曾判定「TIM2 与 TIM3 同抢占级（1/1 与 1/0，GROUP4 下等价）→ ISR 互斥 → Legacy 中不会竞争」。
> **该判定不成立。** 抢占级只保证两个 ISR 不互相嵌套，**消不掉 T1–T2 的时间差** ——
> **硬件 CNT 的回绕不受 NVIC 调度控制，它不等 ISR。**

**定性结论**：R-01 是 **Legacy 与 HAL 均存在的待验证边界风险**，
**不是**「仅当未来从主循环调用才出现」的问题。任何读方落在窗口内即可触发。

**Legacy 未被观测到的可能原因**（**仅为推断，未经实测**，不得据此认定 Legacy 不会发生）：
- 窗口极窄（硬件回绕到 TIM3 ISR 响应之间通常为数百 ns ~ 数 µs）；
- Legacy 读方 1 ms 才执行一次，与窗口重合概率低；
- Legacy 无一致性检查手段，属「未被观测」而非「不会发生」。

**V1 处置**：**不改代码**（遵守规则 4，不与等价迁移混提交）。登记为待验证边界风险；
任何新增读方（观测/遥测）接线时必须写明该窗口的存在与调用上下文。

**V2 候选修法**（任一都需独立登记与验证）：连读两次 CNT 比对 / 读前后各读一次溢出计数取一致值 / 短暂关中断 / 用 32 位级联计数。

> ★ 以上候选**均非无条件正确**（重复读取本身同样可能跨越回绕窗口；关中断需评估对 FOC 时序的影响），
> V2 必须结合 `CNT` / 溢出数 / `UIF` / `DIR` 独立验证后再登记，不得预设某种修法必然成立。

**验证要求**：不得用普通单元测试代替真实中断竞争验证。需覆盖：上溢、下溢、方向反转、跨越零点、连续读取一致性。
**L4 实测前保持 `NEEDS MEASURE`。**

### R-02 ADC 轮询无限等待

`BSP_ADC_ReadAll()` 为 6 次阻塞读，且 `HAL_MAX_DELAY` 无超时。若 TIM1 未运行 → 无 `T1_CC1` 触发 → EOC 永不置位 → **永久阻塞**。

**约束**：只从主循环调用；TIM1 必须先启动。

### R-03 PF10 上电即使能（Legacy 行为）

Legacy `time1.c:29` 在 `Time1_Int_Init()` 里就把 PF10 置高（驱动板 `PM1_CTRL_SD`），**早于任何自检**；配合 `enable_flag = 1`（A 版）即上电闭环。

**V1 更新（2026-10-10，D-20，用户已选择 B 安全优先）**：可下载 HAL 固件已通过 CubeMX 将 PF10 初始值改为 Low（`GPIO_PIN_RESET`），在输出模式前预置锁存位；新增 `BSP_MotorEnable_ForceDisable()` 在四个 BSP 启动前重复禁能，未提供置高 API。Legacy 文件与 `enable_flag` 保持冻结。

**R-03 未关闭**：默认低措施已从 V2-SF-02 前移到 V1，但本机静态证据不能代替实板禁止态验收。板卡版本、R70、OC_OUT、外部下拉、供电/复位/高阻窗口以及 PB12/BKIN 保护链仍未验证；状态机、故障关断/恢复仍属后续 V2。

**因此 `POWER-STAGE ENABLE` 必须保持 `BLOCKED`** —— 软件默认 Low **不能**被当作硬件安全验收通过。PWM 启动可能已使能六路输出，任何逻辑观测都必须物理断开功率直流侧。

## 7. 进入 FOC 前的 Legacy 行为回归测试阶段

在模块迁移顺序（`bsp_encoder → bsp_timer → bsp_motor_enable → bsp_uart`）之后、接入 FOC 之前，**增加一次独立的回归测试**，聚焦三条链路：

| 链路 | 测试内容 |
|---|---|
| **1. 编码器** | 计数值、溢出累计、角度、转速、方向；含 R-01 的竞争边界 |
| **2. 采样** | ADC 原始值、零偏、单位换算、采样调用顺序 |
| **3. PWM** | 三相 CCR 更新、互补输出、更新中断、输出禁止逻辑 |

**三条链在代码层面完成独立验证后，才把 Clarke / Park / PI / SVPWM 接回去。**

## 8. 七条迁移规则

> 已同步写入 [`DMF407_HAL_CMake_模块化重构_Agent任务书.md`](DMF407_HAL_CMake_模块化重构_Agent任务书.md) 作为共同约束。

1. 以 `Template222_A` 为**功能行为基线**，`Template222-100` 为**历史对照基线**，均不得覆盖。
2. 每个模块**先建立函数映射表**，再编写 HAL 封装，不允许一边猜测旧逻辑一边改写。
3. 对控制参数、数据类型、采样顺序、计数溢出、ISR 调度和方向定义执行**差异审计**。
4. 任何「改善代码质量」的调整**不得与 V1 等价迁移混在同一次提交**。
5. 编译通过只能证明 **L2**；没有实测数据，不得宣称 PWM、ADC、电机控制已经等价。
6. 默认禁止驱动功率使能，保持 **`POWER-STAGE ENABLE BLOCKED`**，直至安全验收通过。
7. 每完成一个模块，保存 **Git 提交、编译记录、测试结果及剩余风险**，不要一次性迁移整套 FOC。

## 9. 工程结论

现有 Legacy 并**不是**一份需要彻底推倒重写的废弃代码 —— 它提供了相当完整的控制算法与硬件资源映射。

复现工作的价值不在于写出更多 HAL 代码，而在于把原先散落在 **SPL 调用、全局变量和中断**中的隐含行为，变成**可检查、可回归、可追溯**的工程规范。
