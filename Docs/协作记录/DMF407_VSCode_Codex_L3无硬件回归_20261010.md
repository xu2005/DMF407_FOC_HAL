## 2. 实施方式

在 `tests/host/` 建立最小的宿主机测试工程（CMake + CTest 或等价的一条运行命令）。优先使用本机现有 GCC/Clang/MSVC，不额外安装测试框架。

**必须编译和调用仓库中的真实 `BSP/*.c`**；Mock 仅替代所需 HAL 类型、函数、寄存器和返回值。不要另写一份模仿 BSP 的业务逻辑。若 HAL 依赖导致直接编译难以实现，先选择最小 mock 适配；不要为测试大规模重构生产代码。主机模拟事件是确定性模型，并不能代表外设真实时间过程。

### A. Encoder（优先）
- 验证启动调用与 TIM3 **仅 UIE**、不启用 CC1IE/CC2IE 的软件意图。
- 覆盖正转、反转、`65535→0` 上溢、`0→65535` 下溢、方向反转；断言扩展计数变化。
- 为 **R-01** 单独编写可重现的边界用例：硬件 CNT 已回绕而软件 Update ISR 尚未处理，或读取 CNT/溢出累计期间跨越回绕。记录 ±65536 潜在跳变，不偷偷改算法让测试变绿。
- 已知风险用 **KNOWN RISK（可复现）** 表示；正常路径仍须 PASS。不能称 R-01 已关闭。

### B. ADC
- 给三路 HAL ADC 模拟不同读数，断言严格的 `W→V→BUS→W→V→BUS` 六次顺序，前 3 次丢弃、后 3 次返回。
- 验证关键 HAL 调用顺序及原始数据传递；不额外加入 DMA、Injected ADC、滤波或采样时序推断。

### C. PWM
- 模拟 TIM1 寄存器/比较值接口，验证 U/V/W → CCR1/CCR2/CCR3 的映射及 0、一般值、合法边界值。
- 仅对真实 BSP 已公开接口断言，不预设不存在的 API；必要时依据源码确定测试调用方式。
- **不宣称**模拟 CCR 正确就等于互补 PWM、死区、MOE、BKIN 或真实电平已经验证。
