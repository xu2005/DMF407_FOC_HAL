# V2 · 硬件安全修正清单 — DMF407_FOC_HAL

> **本清单只承载"整改"，不承载"迁移"。** V1 的等价迁移内容在 [`CubeMX配置核对表.md`](CubeMX配置核对表.md)。
>
> 分层理由：如果同时改 HAL、ADC 架构、FOC 调度和控制参数，电机不转时无法判断是哪一层出的问题。V1 先建立可复现基线，V2 再依据原理图与实测做安全性与控制架构优化。

## 使用方式

- V2 的每一项都以 V1 的实测结果为前提。**V1 没测出来的数，V2 不能开工。**
- 每项按固定格式展开：`Legacy 原配置 → 问题 → 修正方案 → 依据 → 是否已实测确认`
- **未实测确认的项不得当作已完成**。
- 证据优先级同 V1：**原理图 / IO 分配表 > 旧代码实际寄存器配置 > 旧代码运行行为 > 旧代码注释 > 推测**

## SF-01 · PB12 / TIM1_BKIN：硬件 Break 到底接不接

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | BDTR 开 `TIM_Break_Enable` + `TIM_BreakPolarity_High` + `TIM_AutomaticOutput_Enable`；但 PB12 在 `time1.c` 里配成 `GPIO_Mode_IN`（普通输入），**没有 `GPIO_PinAFConfig` 到 AF1** |
| **问题** | F4 上 TIM1_BKIN 必须走 AF 才能进到定时器。所以 Legacy 是"**声明了硬件保护，实际保护路径不存在**"——设计意图与硬件行为不一致 |
| **修正方案** | 二选一，取决于实测：<br>**(a) 接通**：PB12 改 AF1 + 确认刹车信号极性 + 设计"Break 触发后如何恢复"的流程（注意 `AutomaticOutput_Enable` 会在下一个更新事件自动恢复输出）<br>**(b) 放弃**：PB12 保持普通输入，明确记录"无硬件 Break"，另建等效保护链（急停 / CTRL_SD 快速关断 / 过流联锁） |
| **依据** | `ATK-DMF407_V1.0原理图.pdf` p1：PB12 复用列含 `TIM1_BKIN`，PM1 接口区有独立 `TIM1_BKIN` 网络标号；IO 分配表标注 PB12 = `TIM1_BKIN` / 驱动板1-刹车信号。**即这不是闲置引脚，是承担保护职责的那一根** |
| **实测确认** | [ ] 未确认 |

- [ ] ★ **不能把 V1 的"Break 照原样 Enable"理解成"隐患已处理"**。V1 的 BDTR 里 Break 是开的，但 BKIN 仍未接通，实际保护为**零**
- [ ] ★ 未接任何保护链之前，A5 功率运行保持 BLOCKED

## SF-02 · PF10 / CTRL_SD：极性与上电顺序

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | `time1.c:29` 在 `TIM1_Int_Init()` 里就把 PF10 `GPIO_SetBits` 置高，**早于任何自检**；随后 `TIM_CtrlPWMOutputs(TIM1, ENABLE)` 使能 PWM 输出 |
| **问题** | 上电瞬间就把驱动板置于"允许输出"状态，没有任何自检、没有故障判据、没有状态机授权。而且真实极性未经验证 |
| **修正方案** | 初始化停在**禁止态**；由应用状态机在自检通过 + 保护链就绪后才显式使能。故障复位流程要显式拉低再释放（见 SF-03） |
| **依据** | `ATK-PD6010B_V1.0原理图.pdf` p1"关断&过流保护"区块原文：`CTRL_SD=0`，H桥无效；`CTRL_SD=1`：未发生过流（`OC_OUT=1`）时光耦导通、H桥有效 |
| **实测确认** | [ ] 未确认 |

> ★ **不要从 IR2110S 的 `SD_IN` 内部逻辑反推 PF10 的有效电平。**
> 厂商教程讲的 `SD_IN=1` 关闭是**芯片内部**信号；`PF10` 是**驱动板级**控制输入，中间经过 `EL357N(C)` 光耦（OC7）+ `BC847PN`（U9），有没有倒相从网络表看不出来。

- [ ] ★ 单板低风险测量：PF10 = 0 / 1 两种电平下，H 桥是否真的禁止 / 允许输出。记录进 V1 第 13 节
- [ ] ★ 确认后把 V1 的 PF10 初始电平改到禁止态，并加显式使能点

## SF-03 · PD6010B 过流保护：R70 决定锁存还是自动恢复

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | 无任何过流处理。`globals.c` 里 `enable_flag=1` 上电即闭环，没有故障判据、没有状态机 |
| **问题** | 不知道过流后会怎样，也就无法设计复位流程 |
| **修正方案** | 先实测 R70 装配状态，再据结果设计：<br>**焊接 R70（锁存）** → 故障后必须显式 `CTRL_SD=0` 才能清除锁存，软件复位流程要"拉低→延时→释放"，不能只清标志<br>**不焊接 R70（周期保护）** → 过流解除后 H 桥自动恢复，软件必须防止"解除即自动重启"，要加故障锁存和人工确认 |
| **依据** | `ATK-PD6010B_V1.0原理图.pdf` p1 区块标注**原文**：<br>「**焊接R70,带锁存保护**：`CTRL_SD=0`，H桥无效；`CTRL_SD=1`：未发生过流(`OC_OUT=1`)时，光耦导通，H桥有效；当发生过流(`OC_OUT=0`)时，在自锁电路作用下 `OC_OUT` 恒为低（即使解除过流状态），光耦关断，H桥关断，直到 `CTRL_SD=0` 时，清除锁存状态」<br>「**不焊接R70,周期保护**：`CTRL_SD=0`，H桥无效；`CTRL_SD=1`，过流时H桥无效，解除过流状态时H桥有效」 |
| **实测确认** | [ ] 未确认 |

- [ ] ★ 拆机确认每块 PD6010B 的 **R70 是否焊接**（两块可能不同）
- [ ] ★ 确认 `OC_OUT` 是否有引到 MCU 可读的引脚（若没有，过流对软件完全不可见）
- [ ] 同区块标注的阈值推导可作参考：`△U = 10K/520K × 3.3V = 64mV`，`△A = 64mV/(2.5V-1.25V) × 10A = 0.51A`

## SF-04 · ADC 架构：从轮询改为 PWM 同步采样

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | 三个 ADC 独立模式、`ContinuousConvMode=ENABLE`、外部触发 `T1_CC1` 下降沿、采样 480 周期；取值靠 `ADC_GetValue()` 里 `while(EOC==RESET);` **阻塞轮询**，`ADC_ProcessData()` 连调 6 次（每个 ADC 读两遍、用第二遍） |
| **问题** | ① `ContinuousConvMode=ENABLE` 时外部触发**只启动第一次转换**，之后 ADC 自由运行（约每 23 µs 一次），采样时刻与 PWM 相位无关 → **根本没构成 PWM 同步采样**<br>② 采样窗口极长：ADC 时钟 21 MHz 时 `480/21e6 ≈ 22.9 µs`（含转换约 23.4 µs），相对 100 µs 级控制周期太大<br>③ 6 次阻塞轮询量级 **70~140 µs**，而这个函数在 FOC 中断里也调用 |
| **修正方案** | 改为标准结构：`TIM1 指定相位 → ADC 注入组触发 → 转换完成中断 → ISR 里直接读 JDR（不等待）→ FOC → 更新 PWM`。<br>三个 ADC 用三重同步或注入组保证同时采样 |
| **依据** | 方案文档 §8.3 / §14；本项属架构优化，非迁移 |
| **实测确认** | [ ] 未确认 |

- [ ] ★ 前置：V1 第 13 节已测出 `ADC_ProcessData()` 实际耗时和 ISR 实际频率
- [ ] 若 V1 实测显示已溢出，则 SF-04 升级为**最高优先级**，不是"以后再说"
- [ ] 用示波器确认采样点不落在开关瞬态窗口内

## SF-06 · TIM1 RCR：中断频率是否翻倍

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | `TIM_RepetitionCounter = 0`，中心对齐模式 |
| **问题** | 中心对齐 + RCR=0 时，计数器**上溢和下溢各产生一次更新事件** → 更新中断频率可能是 PWM 频率的 **2 倍**（≈20.2 kHz 而非注释里的 10 kHz）。连带 `test.c` 的 `current_cycle_counter >= 10` 速度环分频，实际得到的可能是 ~2 kHz 而非 1 kHz |
| **修正方案** | 先把实际值测出来（V1 第 13 节第 06/07 项）。若确认翻倍，则决定：<br>**(a)** 保持 RCR=0，把速度环分频从 10 改成 20（保持速度环 1 kHz 不变）<br>**(b)** RCR 改 1，让一个 PWM 周期一次中断 |
| **依据** | 中心对齐计数区间 `0→ARR→0` = 2×ARR 个计数；RM 关于更新事件与重复计数器的描述。**离线无法完全证实，必须实测** |
| **实测确认** | [ ] 未确认 |

- [ ] ★ 这是 V2 里**最先要做**的一项，因为它决定 SF-04 / SF-05 的时间预算，也决定速度环分频系数

## SF-07 · TIM2 与 PM2 编码器的资源冲突（双轴前提）

| 项 | 内容 |
|---|---|
| **Legacy 原配置** | TIM2 作纯时基（`Time2_Init(999, 83)`）承担 1 ms 角度/转速任务，不配通道 |
| **问题** | 主板 IO 表确认：**PA15 = TIM2_CH1 = `PM2_ENCA`**，**PB3 = TIM2_CH2 = `PM2_ENCB`**。第二轴编码器物理上就挂在 TIM2 的两个通道上。**一个定时器不可能既是自由运行的 1 ms 时基、又是 PM2 的编码器计数器** |
| **修正方案** | 进入双轴阶段时把 1 ms 周期调度换到别的定时器（**TIM6/TIM7 是纯基本定时器、不占引脚，最省事**），把 TIM2 让给 PM2 编码器 |
| **依据** | `ATK-DMF407_V1.0 IO以及接口分配表.xlsx` → `串口&定时器&CAN&SPI` sheet |
| **实测确认** | [ ] 未确认 |

- [ ] V1 先按 Legacy 用 TIM2，但**这一条必须写进工程 README**，不能默认它能延续到双轴

## 附：换算基准（原理图已核实，可直接用作初值）

从 `ATK-PD6010B_V1.0原理图.pdf` p1"三相H桥 / 电压&电流采集"区块标注逐字提取：

```
Diff Gain = 12/(1+1) = 6
Iout = 6 * 0.02Ω * I + 1.25V
```

即 **0.02 Ω 采样电阻 → 差分放大 6 倍 → 输出 = 0.12 × I + 1.25 V**。这解释了 Legacy `USER/current.c` 里 `CURRENT_SENSOR_SCALE = 0.12` 和偏置 `1.250` 的来历——**是原理图推出来的，不是拍脑袋**。

- [ ] ★ 仍应按 SF-04 的改造做零点与增益校准（电阻公差、ADC 参考、走线失调）
- [ ] ★ 母线电压比例（Legacy `calculate_bus_voltage` 里的 `×25`）**未在原理图核实**，必须用万用表对照实测校准
