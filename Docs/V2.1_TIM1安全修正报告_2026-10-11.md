# DMF407 V2.1 TIM1 安全修正报告

日期：2026-10-11。起点：`1676de288df769f62d1aafe22c4e0cff33bed054`；本机受测软件提交：`e5dd16e257c6829e8e5629cdb3a6ecc5118762bf`。继续原分支与 Codex/Trae 历史，本文记录 V2.1 有意差异，不能宣称 V1 等价。

**L4 NEEDS HARDWARE；L5 / POWER-STAGE ENABLE BLOCKED。** 没有烧录、实板操作、接通功率母线或添加 PF10 ForceEnable。软件寄存器模型不证明驱动板禁能有效。

## P0-01：V2-SF-AOE-LOCK

旧初始化锁定 AOE=1、LOCK=1，故障却试图清 `MOE|AOE`。AOE 写入会被锁拒绝，Break 撤销后的 Update 可恢复 MOE。旧 RAM Mock 允许清 AOE，其 PASS 不能支持硬件保护结论。

官方依据：[ST RM0090](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。本轮读取的文档索引 Rev21：§17.4.18（BDTR，p586–587）、§17.3.12（Break，p549–550）、§17.3.2（中心对齐/Update，p529）、§17.3.3（RCR）、§17.4.9（CCER）。LOCK1 固定 AOE、BKE/BKP、DTG 和 CR2 空闲状态配置；MOE、CCxE/NE 仍可写。AOE0 时 Update 不自动置 MOE；AOE1 且 Break 无效时可自动置 MOE。LOCK 在复位后首次 BDTR 写入时确定。HTTP 下载返回错误/HTML，未误当 PDF 归档，依据来自官方文档索引。

本地 CubeF4 V1.28.3 / HAL V1.8.5 的 `stm32f4xx_hal_tim_ex.c:2015–2048`：`HAL_TIMEx_ConfigBreakDeadTime` 在局部 `tmpbdtr=0` 中组合配置，最后一次写 BDTR。生成 `MX_TIM1_Init` 在 PWM/通道配置之后调用它，启动前没有第二次 BDTR 配置。因此首次写入必须锁定 AOE0，不能依靠运行时清锁定位补救。

通过 CubeMX 6.12.0 原生 CLI `set ip parameters TIM1 AutomaticOutput TIM_AUTOMATICOUTPUT_DISABLE` → `config save` → `project generate` 实施，完整命令和回读/生成日志已归档。默认 DISABLE 值在 `.ioc` 中由 CubeMX 删除，这是原生序列化结果；最终查询 AOE=DISABLE、OSSR=DISABLE，生成代码明确写 AOE=DISABLE。中间误改 OSSR 随后恢复；首次非 UTF-8 生成损坏的中文注释从原快照恢复，再以 `-Dfile.encoding=UTF-8` 原生生成，最终没有注释损坏或额外配置改动。

| 配置 | 原版 | V2.1 |
|---|---|---|
| AOE | ENABLE | DISABLE（唯一 TIM1 外设语义变化） |
| LOCK | Level1 | Level1，未降低 |
| BKE/BKP | ENABLE/HIGH | 保留，PB12仍普通输入 |
| OSSR/OSSI | DISABLE/DISABLE | 保留 |
| PSC/ARR/RCR/CMS | 83/99/0/中心对齐1 | 保留 |
| PWM/CCR初值/极性/DTG | PWM1/0/HIGH/84 | 保留 |
| TRGO/ARPE/CKD | OC1REF/ENABLE/DIV1 | 保留 |

`generated-config.diff` 保存完整外设生成差异；`preserved-source.diff` 为空：Legacy、Control、Motor、main、ADC/GPIO/MSP、工具链及生成 CMake 无语义变化。166 个 USER CODE 块核对，163 个保留，3 个为后续有意新增的 DWT 插桩。

故障函数仅清可写 MOE，再关六路 CCER、CEN/UIE，前后强制 PF10 Low，不尝试清 AOE。启动发现 AOE1 或 LOCK≠1，锁存 `BSP_FAULT_TIM1_CONFIG` 并拒绝启动。对于继承的旧 AOE1/LOCK1 配置，模型明确允许软件 UEV 再置 MOE；此时 CCER/CEN/UIE 仍关闭、受检 Start 拒绝、PF10保持目标禁止态，**不能宣称 MOE 永远为0**，必须复位并加载新配置。

## P0-02：V2-SF-DEFAULT-PWM

修改前 OFF/ON 都可达：`main → App_NoPower_Start → BSP_PWM_StartChecked → 六路 HAL PWM/PWMN Start → MOE/CCER/CEN`。

修改后默认 OFF：`App_NoPower_Start → 配置检查 → ADC/Encoder Start → TIM2/TIM4 Start → BSP_TIM1_StartDiagnosticChecked`。诊断入口禁输出、清 UIF、开 UIE/CEN，无 PWM/PWMN Start、不运行 PI/SVPWM、不动态写 CCR。

显式 ON 才可达六路 Start 与 FOC Pipeline，仍只发 PF10 RESET。受检 Start/Stop/CCR 发布保存并恢复 PRIMASK，避免普通 IRQ 在检查后锁存故障、主循环随后又开 MOE。非屏蔽异常、调试器、外设损坏和电气状态不在该原子性保证内。

| 预期阶段（尚未实板读回） | AOE | LOCK | MOE | CCER & 0x555 | CEN/UIE |
|---|---:|---:|---:|---:|---|
| MX_TIM1_Init 完成 | 0 | 1 | 0 | 0 | 0/0 |
| OFF 诊断启动 | 0 | 1 | 0 | 0 | 1/1 |
| ON 启动且 Break 无效 | 0 | 1 | 软件置1 | 0x555 | 1/1 |
| 新配置故障锁存 | 0 | 1 | 0 | 0 | 0/0 |

初始化 BDTR 组合预期 `0x3154`，ON且Break无效预期 `0xB154`。MOE、CCER、CEN 是不同定时器控制门；PF10 Low 是 GPIO 命令，不能等同于外部驱动物理禁能，也不以 CCR0 推断六路电平。

ADC 保留 TIM1_CC1、FALLING 首触发、连续转换，未改 DMA/Injected/TRGO。依据 [RM0090 §13.13.3](https://www.st.com/resource/zh/reference_manual/DM00031020.pdf)，EXTSEL0000 选择 TIM1_CC1，不能把 OC1REF/TRGO/引脚波形混作同一信号。关闭 MOE/CCER 时由内部时基继续产生比较事件是待测方案，**不保证首触发**，尤其 CCR1=0、FALLING 组合。无触发时有限 Poll 超时锁存 ADC_READ，绝不打开 PWM 绕过；独立 OFF 超时测试覆盖失败分支。

## P0-03：V2-SF-FAULT-LOCK-MODEL

模型在实际 `CLEAR_BIT(BDTR,MOE)` 写边界拦截，按首次写/LOCK1 屏蔽锁定位，模拟 Break 清 MOE、显式 Update 自动置 MOE。假 HAL Start 只置对应 CCxE/NE、MOE/CEN，不伪造 AOE 写入。模型仅覆盖 BDTR 控制规则，不模拟 ADC、电气波形、APB同步/NVIC时序或 LOCK2/3 的全部外围寄存器。

| 注入/边界 | 真实运行的用例 | 软件断言 |
|---|---|---|
| 六路 Start/Stop 失败 | 原6+6项 | 首故障保持、所有通道禁能；Stop失败仍禁止输出 |
| ADC Start、六处Poll ERROR/BUSY/TIMEOUT | 原3+18项 | 有限返回、停止ADC、旧输出不部分覆盖 |
| sector0、NaN/Inf/负值/越界/空指针 | 原8项 | 不写CCR、锁存CONTROL |
| Encoder回绕/反转/延迟ISR/32768/int64边界/超期 | 原V1/V2 + v21_encoder_ambiguous | 有界计数及异常锁存 |
| TIM2/TIM4启动、Encoder Start/Stop失败 | 原4项 | TIMER/ENCODER首故障与失败回滚 |
| 故障后再Start、再Update | 所有fault_check分支 | App/PWM/诊断/TIM2/4/ADC/Encoder受检Start拒绝，正常AOE0时MOE不恢复 |
| 初始MOE1/AOE1/LOCK1、错误LOCK | v21_locked_aoe/initial_moe/wrong_lock及OFF项 | 复现旧缺陷、拒绝坏配置、关闭可写输出门 |
| 早期初始化失败 | 原v2_early_init | htim1.Instance=NULL，无TIM1解引用，仍发PF10 RESET并锁存INIT |
| 前次ADC/App状态保持、独立原始码龄期 | v21_adc_previous/app_adc_transaction/sample_age | 完整发布，20ms有效/21ms拒绝 |

真实 `Error_Handler` 保留 GPIOF 时钟使能 → SafetyFault(INIT) → 禁 IRQ → 无限停留。主机执行底层安全动作，ARM编译/源码审核覆盖入口，未声称执行了该无限循环或测过复位引脚波形。

低层 V1 未受检接口仍用于历史回归，固件受检路径不调用它们，不能用于生产恢复。首故障仅 MCU reset 清除，无自动恢复 API。PB12、驱动保护链仍未实测。

## P1 复核与门禁

TIM1CLK理论168MHz，PSC+1=84，计数2MHz；中心对齐周期2×ARR=198计数，PWM≈10.101kHz，RCR0在上/下端各Update，Update≈20.202kHz（49.5µs）。速度环10:1理论≈2.020kHz，不能称1kHz。频率、分频和数学公式均未修改；实际时钟、漏IRQ和WCET仍需L4。

`DMF407_DWT_DIAGNOSTICS=OFF` 默认关闭。ON在TIM1 IRQ C函数入口附近取CYCCNT，HAL IRQ → Callback → FOC/安全分支返回后记录last/max/count，没有阻塞UART/printf/动态内存。覆盖HAL/回调整个C调用区间及其中抢占，**不包含硬件异常入/出栈、最终统计自身等全部开销，不能直接当真实WCET**。32位无符号差处理回绕，区间须小于一整圈（168MHz约25.6秒）；调试暂停、DWT是否运行和测量开销都须登记。不支持CYCCNT则enabled0。

Encoder相邻真实采样位移必须<32768，精确32768/int64越界拒绝；CNT不能恢复或检测所有丢整圈，2ms HAL tick粗检查不能替代位移约束。V1 R-01仍KNOWN_RISK。

ADC W/V/BUS/W/V/BUS六次顺序、单次2ms、完整成功后发布、20ms原始码龄期、2ms编码器间隔均保留，轮询只在主循环。SysTick饥饿、三路自由运行非同步、实际采样龄期仍需L4。

本机软件验证PASS，见 [测试与构建证据](V2.1_测试与构建证据_2026-10-11.md)。真实AOE/LOCK/MOE/CCER/CEN/UIE读回、后续Break/Update、ADC首触发、PF10/CTRL_SD/R70/PB12、实际频率与完整WCET均未验收；L5继续BLOCKED，PR合并不代表功率放行。
